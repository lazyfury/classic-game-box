# 补码 Two's Complement

> 目标：理解 CPU 如何在没有减法器的情况下做减法，以及为什么 `0xFF` 同时可以是 255 和 -1。
> **这一章是 6502 overflow flag（V）的根基——模拟器里最常写错的标志位。**

---

## 1. 问题：硬件只有加法器

做一个十进制加法器很容易：逐位相加、处理进位。

做一个**减法器**要多一套电路。而在 1975 年的芯片上，晶体管是昂贵的。

**能不能只用加法器实现减法？**

数学上可以：`a - b = a + (-b)`

只要我们能**用 bit 表示负数**。

---

## 2. 三种候选方案

### 方案 A：符号位 + 数值（原码 signed-magnitude）

最高位当符号位：`0` 正，`1` 负。

```
0000 0011 = +3
1000 0011 = -3
```

**问题：**

- 有两个零：`0000 0000` (+0) 和 `1000 0000` (-0)
- 加法电路必须判断符号，还是要两套逻辑
- `+3 + (-3)` 不能直接相加得到 0：

```
  0000 0011
+ 1000 0011
-----------
  1000 0110   = -6   ✗
```

**失败。**

### 方案 B：反码（ones' complement）

负数 = 逐位取反。

```
0000 0011 = +3
1111 1100 = -3
```

加法试试：

```
  0000 0011   (+3)
+ 1111 1100   (-3)
-----------
  1111 1111   (-0)
```

得到了"负零"。还差 1 才是 0。

**还是有 +0 / -0 两个零，还是要"循环进位"的额外修正。** 不完美。

### 方案 C：补码（two's complement）✅

负数 = **逐位取反，再加 1**。

```
-3 = ~3 + 1
   = 1111 1100 + 1
   = 1111 1101
```

加法：

```
  0000 0011   (+3)
+ 1111 1101   (-3)
-----------
1 0000 0000
```

第 9 位溢出被**丢弃**，结果是 `0000 0000` = 0。

**完美：加法和减法用同一个电路，只有一个零，不需要任何修正。**

---

## 3. 硬件实现：这就是它为什么叫"二补数"

一个 8 位加法器只是 8 个全加器链在一起。要做 `a - b`：

1. 把 `b` 的每一位取反（用 8 个 NOT 门，几乎免费）
2. 把最低位的进位输入（carry-in, Cin）设为 1

```
         b = 0000 0011
      ~b   = 1111 1100     <- 8 个 NOT 门
      +1   = 1111 1101     <- 把加法器的 Cin 拉高
```

**"加 1" 不是额外电路，仅仅是让最低位进位输入为 1。** 这就是为什么补码在硬件上几乎是免费的。

6502 的 ALU 就是这样工作的。subtract 指令和 add 指令共用同一个加法器。

---

## 4. 完整的 8 位补码表

```
bits       unsigned    signed (two's complement)
0000 0000      0            0
0000 0001      1            1
...
0111 1111    127          127     <- 有符号最大值
1000 0000    128         -128     <- 有符号最小值
1000 0001    129         -127
...
1111 1110    254           -2
1111 1111    255           -1     <- 有符号 -1
```

**规律：**

```
MSB = 0  ->  非负，值就是无符号值
MSB = 1  ->  负，值 = 无符号值 - 256
```

验证：`0xFF` 无符号 255，有符号 `255 - 256 = -1` ✓
验证：`0x80` 无符号 128，有符号 `128 - 256 = -128` ✓

**这是 8 位不是巧合：有符号范围是对称的 `-128 .. +127`，但负数比正数多一个。**

---

## 5. 为什么 `0xFF` 同时是 255 和 -1？

因为 **bit 本身没有类型**。

```
1111 1111
```

没有任何 bit 说"我是负数"。**是解释者决定的：**

```cpp
u8 raw = 0xFF;
std::cout << (int)raw;                 // 255
std::cout << (int)bit::as_signed(raw); // -1
```

CPU 内部只存 bit。它有**两个标志位**来同时记录两种解释的结论：

- **C (Carry)** — 无符号溢出
- **V (Overflow)** — 有符号溢出

两者可以同时发生，也可以只发生一个。这是初学模拟器最大的坑。

---

## 6. 溢出标志 V：补码的核心难点

### 6.1 无符号溢出（C flag）

把 bit 7 的进位丢掉时，C 置位。

```
  1111 1111   (255)
+ 0000 0001   (1)
-----------
1 0000 0000   -> C = 1，结果 0
```

**判断：无符号结果 ≥ 256。**

### 6.2 有符号溢出（V flag）

有符号溢出和进位**完全不同**。

考虑 `+127 + 1`：

```
  0111 1111   (+127)
+ 0000 0001   (+1)
-----------
  1000 0000
```

bit 7 进位了吗？**没有**（bit 6 进位，bit 7 没进）。所以 **C = 0**。

但结果 `1000 0000` 按有符号解读是 **-128**！

```
127 + 1 = -128   ✗
```

**这才是有没有符号溢出：正数 + 正数 = 负数。**

判断规则（两个操作数符号相同，结果符号却不同）：

```
V = 1  当且仅当  (a 和 b 同号) 且 (result 与 a 异号)
```

用位运算表达：

```cpp
// 等价于 ((a ^ result) & (b ^ result) & 0x80) != 0
bool v = (~(a ^ b) & (a ^ result) & 0x80) != 0;
```

### 6.3 完整对照

| 例子 | C | V | 原因 |
|------|---|---|------|
| `0x7F + 1` (+127+1) | 0 | **1** | 无符号没进位，有符号溢出 |
| `0xFF + 1` (-1+1) | **1** | 0 | 无符号进位，有符号正确得 0 |
| `0xFF + 0x01` 看成 -1+1 | — | 0 | 结果 0 正确 |
| `0x80 + 0x80` (-128-128) | **1** | **1** | 两者都溢出 |
| `0x50 + 0x50` (80+80=160) | 0 | **1** | 160 超出 +127 |

**这张表会在 Phase 1 实现 ADC 指令时直接变成测试用例。**

## 7. 补码的运算性质（写测试时用得上）

```cpp
// 1. 取反加一 = 取负
negate(x) == ~x + 1

// 2. 负负得正
negate(negate(x)) == x          // 对所有 256 个值成立

// 3. 唯一零
negate(0) == 0

// 4. 减法就是加负数
a - b == a + negate(b)          // 在 u8 模 256 意义下

// 5. 0x80 取负是自己
negate(0x80) == 0x80            // -(-128) 溢出，仍是 -128
```

第 5 条是个有趣的边界：`-128` 取负仍然是 `-128`，因为没有 `+128`。

## 8. 6502 中的实际使用

### 8.1 有符号比较

6502 没有"有符号比较"指令。程序用 `CMP` + `BVC/BVS` 组合：

```
CMP  #$80     ; 比较
BVC  ...      ; 如果 V=0，用 C 判断
BVS  ...      ; 如果 V=1，用 C 取反判断
```

**不理解 V，就无法正确实现分支指令 → 游戏行为会错乱。**

### 8.2 相对寻址的分支偏移量

分支指令的偏移量是**有符号 8 位**（-128..+127）：

```
B0 05   -> 向前跳 5  字节
B0 FB   -> 向后跳 5  字节   (0xFB = -5)
```

`0xFB` 补码 = `256 - 5 = 251` → `-5`。计算目标地址必须用有符号解释：

```cpp
// 错误：pc += offset;
// 正确：
pc = static_cast<u16>(pc + bit::as_signed(offset));
```

**这是新手写 6502 第一个大 bug 的高发区。**

### 8.3 SBC 指令

`SBC`（subtract with carry）在 6502 上实际执行 `A + ~M + C`。
C 在这里表示"没有借位"。这套约定完全建立在补码之上。

## 9. 自测

1. `-5` 的 8 位补码是什么？
2. `0x80` 作为有符号数是几？
3. `0xFF + 0x02` 的 C 和 V 分别是多少？
4. 为什么补码只有一个零？
5. 分支偏移 `0xFE` 表示跳几字节？

<details>
<summary>答案</summary>

1. `~5 = 1111 1010`，`+1 = 1111 1011` = `0xFB`
2. -128
3. `0xFF + 0x02 = 0x01`，有第 9 位进位（C=1）；`-1 + 2 = 1` 正确，V=0
4. 因为 `~0 + 1 = 0`，没有"负零"的位置；`0x80` 被用来表示 -128
5. `0xFE = 254`，有符号 `254 - 256 = -2`，向后跳 2 字节

</details>
