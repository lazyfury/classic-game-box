# 十六进制 Hexadecimal

> 目标：理解为什么程序员偏爱十六进制，以及 `0x42` 为什么就是 `0100 0010`。

---

## 1. 问题：二进制太长了

写 NES 程序时你会看到这样的内存：

```
101010011000000010000000000000010000010000000010
```

这是在说什么？人眼无法快速处理连续的 0/1。

十进制也不方便：

```
10101001 = 169
```

**169 和这些 bit 之间没有直观联系。** 你需要心算 128+32+8+1。

---

## 2. 十六进制是二进制的"压缩格式"

关键事实：

```
2^4 = 16
```

**4 个 bit 恰好能表示 16 种组合 (0–15)。**

所以：**1 个十六进制位 = 4 个 bit = 1 个 nibble（半字节）**

```
1 byte = 8 bit = 2 个十六进制位
```

这就是全部秘密。十六进制不是为了数学，是为了**让人能一眼读懂 bit**。

---

## 3. 对照表

| 十进制 | 二进制 | 十六进制 |
|-------|--------|---------|
| 0 | 0000 | 0 |
| 1 | 0001 | 1 |
| 2 | 0010 | 2 |
| 3 | 0011 | 3 |
| 4 | 0100 | 4 |
| 5 | 0101 | 5 |
| 6 | 0110 | 6 |
| 7 | 0111 | 7 |
| 8 | 1000 | 8 |
| 9 | 1001 | 9 |
| 10 | 1010 | A |
| 11 | 1011 | B |
| 12 | 1100 | C |
| 13 | 1101 | D |
| 14 | 1110 | E |
| 15 | 1111 | F |

**A–F 只是"10–15"的单个符号**，因为每一位必须恰好占 4 bit。

### 记忆技巧

```
8 - 4 - 2 - 1
```

这四位的权重。看到 `1101`：8+4+0+1 = 13 = `D`。

---

## 4. 把二进制转成十六进制：每 4 位切一刀

```
1010 1001
 \  / \  /
  A     9
```

结果：`0xA9`

再看：

```
0100 0010
 \  / \  /
  4     2
```

结果：`0x42`

**这就是 `0x42 == 0100 0010` 的原因**——不是巧合，是定义。

> `0x` 前缀来自 C 语言，表示"后面是十六进制"。
> 汇编里用 `$`：`LDA #$42` 和 C 里的 `0x42` 是同一个值。
> 这正是 AGENTS.md 要求解释的 `$` 符号。

---

## 5. 反向：十六进制转二进制

`0xB7`：

```
B -> 1011
7 -> 0111
```

结果：`1011 0111`

**永远补满 4 位。** `0x7` 是 `0111`，不是 `111`。少了前导零会切断字节边界。

---

## 6. 一个 byte 的范围

```
0x00 = 0
0xFF = 255
```

所以：

```
1 byte  ->  0x00 .. 0xFF
2 bytes ->  0x0000 .. 0xFFFF   (0 .. 65535)
```

NES 地址空间正好是 `0x0000`–`0xFFFF` = 64KB。

---

## 7. 为什么程序员"觉得"十六进制好读

真实例子。NES 的 reset 向量存在 `0xFFFC`，它指向程序入口：

```
[0xFFFC] = 0x00
[0xFFFD] = 0x80
```

CPU 读取两个字节，组装成 `0x8000`，然后跳到那里执行。

用十六进制，`0xFFFC` 一眼就能看出：

- `FF` 在高端（`0xFFFC` 靠近地址空间顶部）
- `FC` 是低端

用十进制写 `65532`，你看不出任何结构。

**十六进制保留了 bit 的结构，十进制把它抹掉了。**

---

## 8. 常见陷阱

### 陷阱 1：忘记补零

```cpp
bit::to_hex(u8{0x05});   // "0x05"  正确
// 打印成 "0x5" 在字节流里会破坏对齐
```

所以我们的 `to_hex()` 始终补满两位。

### 陷阱 2：混淆 `0x` 和十进制

```cpp
int a = 10;    // 十
int b = 0x10;  // 十六
```

`b == 16`，不是 10。

### 陷阱 3：把十六进制当作"另一种数"

十六进制**不是**另一种数值，它是**同一种数值的另一种写法**。`0x42` 和 `66` 是同一个数，就像"四十二"和"42"。

---

## 9. 在 C++ 里

```cpp
u8 opcode = 0xA9;      // LDA immediate
u16 vector = 0xFFFC;   // NMI 向量地址
```

`bit::to_hex()` 输出：

```cpp
bit::to_hex(u8{0xA9})    // "0xA9"
bit::to_hex(u16{0xFFFC}) // "0xFFFC"
```

## 10. 自测

1. `0xC0` 的二进制是什么？
2. `1011 0011` 的十六进制是什么？
3. `0x10` 的十进制是多少？
4. 为什么 1 byte 恰好是 2 个十六进制位？
5. NES 的地址 `0x8000` 用十进制写不容易看出什么信息？

<details>
<summary>答案</summary>

1. `1100 0000`
2. `0xB3`
3. 16
4. 因为 1 位十六进制表示 4 bit（2^4=16），而 1 byte = 8 bit = 4+4
5. `0x8000` 一看就知道在高地址区（bit 15 是 1，即 32KB 以上），`32768` 则看不出；而且 `0x8000` 的 `80` 直接对应二进制 `1000 0000`

</details>
