# 二进制基础 Binary

> 目标：理解计算机为什么只能用 0 和 1，以及如何用 bit 拼出 NES 里的每一个数字。

---

## 1. 为什么是二进制

计算机的底层是**晶体管**。一个晶体管可以处于两种稳定状态：

```
导通 / 截止
高电压 / 低电压
1 / 0
```

关键不是"电子只有两种状态"，而是**两种状态最可靠**。

科学家早期尝试过三进制、十进制机械计算机，但问题在于：

| 进制 | 需要区分的电压区间 | 噪声容限 |
|------|------------------|---------|
| 二进制 | 2 个 | 大 → 可靠 |
| 十进制 | 10 个 | 小 → 易出错 |

如果要在 0V–5V 里区分 10 个等级，每一级只有 0.5V 的余量。电压稍微漂移，`7` 就会被读成 `6`。
只区分"有电/没电"（比如 0V 和 5V），噪声容限就有 2.5V。**这是工程上的选择，不是数学上的必然。**

所以：**计算机使用二进制，是因为物理器件最容易可靠地表示两种状态。**

## 2. bit / byte / word

### bit

**bit**（比特）是最小单位，只能是 `0` 或 `1`。

### byte

**byte**（字节）= 8 bit。

为什么是 8？历史上出现过 6 bit、7 bit、9 bit 的机器。8 bit 胜出的原因很实际：

- 能表示 0–255，足够编码 ASCII 字符
- 是 2 的幂，方便硬件对齐、寻址、拆分
- 能放下两个十六进制位（见 [hexadecimal.md](hexadecimal.md)）

### word

**word**（字）是 CPU 一次能处理的数据宽度。

> NES 的 6502 是 **8 位 CPU**，所以它的 word = 1 byte。
> 但它的**地址**是 **16 位**（2 byte），因为 `2^16 = 65536`，需要寻址 64KB。

**注意：word 的宽度不是固定值，它由架构决定。** 现代 Mac 上 `word` 是 64 位。

## 3. 一个 byte 的结构

```
bit index :   7   6   5   4   3   2   1   0
weight    : 128  64  32  16   8   4   2   1
```

每一位有一个"权重"，是 2 的幂：

```
bit 0 -> 2^0 = 1
bit 1 -> 2^1 = 2
bit 2 -> 2^2 = 4
...
bit 7 -> 2^7 = 128
```

**低位（LSB, Least Significant Bit）** 在最右边 = bit 0
**高位（MSB, Most Significant Bit）** 在最左边 = bit 7

### 例子：`0100 0010` 是多少？

只有 bit 6 和 bit 1 是 1：

```
64 + 2 = 66
```

### 例子：`1010 0101` 是多少？

```
128 + 32 + 4 + 1 = 165
```

## 4. 二进制加法：进位（carry）

小学的十进制加法逐位相加、逢十进一。二进制只是逢二进一。

```
  0000 0111   (7)
+ 0000 0001   (1)
-----------
  0000 1000   (8)
```

再看一个会进位的：

```
  1111 1111   (255)
+ 0000 0001   (1)
-----------
1 0000 0000   (256)
```

第 9 位放不进 8 bit 的寄存器，**它被丢掉了，结果变成 0**。

这不是 bug，这正是 NES 里 **carry flag (C)** 存在的原因：CPU 把丢掉的这一位存进 C 标志，程序才能做多字节加法。

```cpp
u8 a = 0xFF;
u8 b = 0x01;
u8 r = a + b;   // r == 0x00，进位消失在类型里
```

**这条规则贯穿整个模拟器：所有算术都必须在固定宽度里进行，溢出必须显式处理。**

## 5. 二进制减法：借位（borrow）

```
  0000 1000   (8)
- 0000 0001   (1)
-----------
  0000 0111   (7)
```

问题：如果 `小 - 大` 怎么办？

```
  0000 0001   (1)
- 0000 0010   (2)
-----------
  ???? ????
```

硬件里没有"负号"。解决方案是**补码**——见 [twos-complement.md](twos-complement.md)。
简单说：CPU 把减法变成"加上一个负数"，而负数用 bit 模式表示。

## 6. 在 C++ 里写二进制（C++14 起）

```cpp
u8 a = 0b0100'0010;   // 分隔符 ' 只是给人看的，编译器忽略
u8 b = 0b1010'0101;

static_assert(a == 66);
static_assert(b == 165);
```

> C++14 引入的 `0b` 前缀和 `'` 数字分隔符，让二进制字面量第一次变得可读。
> 这在写模拟器时极其重要——你会一直盯着 bit 看。

---

## 7. 为什么这对 NES 重要

后面每一章都会用到这一节：

| 场景 | 用到的二进制知识 |
|------|----------------|
| Opcode `0xA9` | 8 个 bit 决定"执行哪条指令"和"怎么取操作数" |
| 状态寄存器 `P` | 8 个独立的 1-bit 标志（N V - B D I Z C） |
| 地址 `0x8000` | 16 个 bit = 2 个 byte |
| 调色板索引 | 6 bit 值（0–63） |
| OAM 属性字节 | 每个 bit 含义不同（翻转、优先级、调色板） |

## 8. 自测

1. `0b1100 0000` 的十进制值是多少？
2. 一个 byte 最多能表示多少个不同的值？
3. `0xFF + 0x01` 在 `u8` 里等于多少？为什么？
4. bit 5 的权重是多少？
5. 为什么 NES 的地址是 16 位而不是 8 位？

<details>
<summary>答案</summary>

1. 192（128 + 64）
2. 256（2^8），范围 0–255
3. `0x00`，第 9 位溢出被丢弃，丢失的位由 carry flag 记录
4. 32（2^5）
5. 8 位只能寻址 256 个地址，放不下 NES 的 2KB RAM + PPU 寄存器 + ROM。16 位给出 65536 个地址 = 64KB，正好是 6502 的地址空间。

</details>
