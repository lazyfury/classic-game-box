# 架构决策记录（ADR）

一条**已定型、且之后不容易反悔**的架构决定 = 一个文件。

## 为什么要有这个目录

- 边界矩阵（[`CONVENTIONS.md`](../../../CONVENTIONS.md)）说的是「**现在**谁依赖谁」；
  这里记录的是「**当初为什么**这么定、否决了什么」。
- 只追加、不改写：决定变了就新加一条「`00xx` 取代 `00ab`」，旧条目留着看历史。
- 目的：后来的人（或 agent）不会把已否决的方案再实现一遍，也不会在不知道约束的情况下改边界。

## 格式

每个文件回答同一组问题，半页到一页即可：

```
# 00xx 标题
- 状态：已接受 / 被 00yy 取代 / 已否决（回溯整理的不写具体日期，除非确知）
- 背景：当时的约束与问题
- 决定：选了什么
- 否决的方案：还考虑过什么，为什么不选
- 后果：得到什么、付出什么代价
- 权威文档：细节以哪篇文档/代码为准
```

## 什么时候新增一条

按 [`CONVENTIONS.md`](../../../CONVENTIONS.md)「改动边界」：动公共 API、依赖方向、
路线图之前，先在这里加一条，再改契约，最后改校验脚本。顺序不能反。
