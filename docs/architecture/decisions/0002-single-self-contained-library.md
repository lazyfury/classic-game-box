# 0002 单库、自包含、可切换

- 状态：已接受（回溯整理）
- 背景：早期用 `library_dirs` 支持多个游戏目录并合并显示。跨目录合并时，同名 ROM、
  重复截图、存档归属都没有清晰规则，备份/迁移要手动挑选多个目录。
- 决定：
  - 游戏库是**一个根目录**，用 `--library-dir` 或「打开游戏库…」选定。
  - DB、截图、存档、金手指**都在库根下**；整个文件夹拷走就是完整备份。
  - 单库、可切换，不做多库合并。旧 `library_dirs` 只在迁移时读一次（取第一个）。
  - app data 只留 `settings.json`、`cores`、`system`（BIOS 不放库里，避免
    `neogeo.zip` 被扫成街机 ROM）。
  - ROM 路径以**相对库根**存入 DB，库跨 macOS/Windows 打开安全。
- 否决的方案：
  - 多目录合并 —— 冲突与去重规则复杂，备份不完整。
  - 库放 app data —— ROM 与存档分家，用户找不到自己的东西。
- 后果：
  - `Library::open` 只认一个根；「整个文件夹 = 库」的心智模型简单。
  - 代价：不能同时挂多个目录；换库要显式切换。

  [`../../../src/library/db.rs`](../../../src/library/db.rs)。
